## 2. 目的と範囲

### 2.1 目的
ユーザーが撮影した動画に映る人物の**顔だけ**を、**AIで作った架空の人物の顔**に置き換える、汎用の動画変換ソフトを構築します。

### 2.2 想定する用途
- 顔を出さずに動画を投稿する（運動、ダンス、解説、日常の記録など）
- 動画に映った人物のプライバシーを守る
- 1本の元動画から、違う顔のバージョンを複数作ることもある

### 2.3 要件

| ID | 要件 |
|---|---|
| R1 | **体、髪型、服、背景はそのまま残し、顔だけを置き換える**（必須） |
| R2 | **元の動画の表情を保つ**。力んだ顔、苦しい顔、笑顔、口の開き、眉の動きなどを、元の動画と同じように再現する（必須） |
| R3 | 完成度を最優先する（U2） |
| R4 | 顔の参照写真を**複数枚**渡せる |
| R5 | 動画に**複数人**が映っていても、置き換える人物を指定できる。人ごとに別の顔を割り当てられる |
| R6 | 速い動き、回転、全身が映る引きの画（ダンスなど）、体が多く映る場面（上半身裸など）に対応する |
| R7 | GUIで操作する（U3） |

### 2.4 範囲外
- 体や頭部全体（髪を含む）の置き換え
- 音声の変換（後のフェーズで検討します。16.3節を参照）
- 商用サービスとしての提供

## 3. 利用条件と安全要件（必須）

| ID | 内容 |
|---|---|
| S1 | **置き換え先の顔は、AIで作った実在しない人物に限る**。実在の人物（芸能人、知人など）の顔や、実在の人物に似せた顔は使わない |
| S2 | **置き換え元の動画は、ユーザー本人が映っているもの、または映っている人から了承を得たものに限る**。ネット上の他人の動画は使わない |
| S3 | 公開する動画には、各プラットフォームのルールに従って「AIで加工・改変した」表示をする |
| S4 | ツールの安全機能（FaceFusionのコンテンツ判定など）を、無効にしたり回避したりしない。誤って判定された場合は、その素材をそのツールで処理しないなどの運用で対応する |
| S5 | 書き出した動画に「AIで改変した」ことを示すメタデータを付ける（3.1 節） |

### 3.1 実装すべき安全機能
- 書き出した動画に「AIで改変した」ことを示すメタデータを付けられるようにする（任意で画面上にも表示）

## 4. 用語

| 用語 | 意味 |
|---|---|
| ソース（source） | 置き換え先の顔。AIで作った架空の人物の写真 |
| ターゲット（target） | 置き換え元の動画、またはその中の人物 |

| DFM | DeepFaceLab / DeepFaceLive で使う、特定の顔に特化して学習させたモデルの形式 |
| シーンプロファイル | 場面の種類ごとにまとめた推奨設定（10章） |

### 6.2 VisoMaster Fusion を中核にする理由
- 編集ソフトのような画面（プレビュー、タイムライン、顔の一覧、設定パネル）で操作できる
- タイムラインのマーカーで、フレーム単位で設定を保存し、場面ごとに設定を変えられる【確認済み】
- 人物ごとに顔素材を割り当てられ、似ている度合いの判定の厳しさを調整できる。ByteTrack で追跡するので、顔が重なったり一瞬画面外に出たりしても同じ人として追い続ける【確認済み】
- 表情を戻す機能、口元を戻す機能（Restore Mouth）、目元を戻す機能（Restore Eyes）、口の位置合わせ（Mouth Fit & Align）がある【確認済み】。表情を部位（目、眉、口、あご）ごとに調整できるとマニュアルにある【未確認：実際の画面で確認】
- マスクの種類が多い（遮蔽物、XSeg、テキスト指定、顔のパーツ分け、境界、横顔用 profile-angle、口元用）【確認済み】
- 肌の質感を保つ機能がある（Diffusion系のノイズ除去 ReF-LDM、元動画の質感を移す Texture Transfer、自動の色合わせ AutoColor、最後の色移し）【確認済み】
- 書き出し前に問題のあるフレームを探す機能（Issue scanning）、ジョブ管理機能がある【確認済み】
- 2つ目の顔交換（Secondary Swapper）で、2つのモデルの結果を混ぜられる【確認済み】
- 顔の形の調整（Face Shaping：顔を細く、あごを細く、額、あごの長さ、顔の長さ）がある【確認済み】
- DFM モデルに対応している【確認済み】
- 必要な VRAM は最低 6GB、推奨 8〜12GB 以上。NVIDIA ドライバは 576.57 以上を推奨【確認済み】

### 6.3 入手元の注意（重要）

- 入手先は公式GitHubのみ：https://github.com/VisoMasterFusion/VisoMaster-Fusion
- リリースページで「Latest」が付いているのは v3.9.3（AlphaFace非搭載）。
- 使うのは v3.12.3 で、v3.12.3 のリリースページから直接ダウンロードする（Phase 0で確認済み）。

## 9. 処理の流れ（制作手順）

### 9.1 撮影（完成度への影響が最も大きい）
コンパニオンツールにも撮影ガイドとして表示する。
- 4K・60fps で撮る。全身が映る場合は特に 4K が必須
- シャッタースピードを速めにする（目安は 1/120 秒以上）
- 顔に均一に光を当てる。強い影や逆光は避ける
- 髪は顔にかからないようにまとめる
- 腕や道具で顔が隠れる時間が短くなるカメラ位置にする
- 回転の多い動きは、正面から撮ったものを本番用にする
- 可能なら SDR で撮る（HDR の扱いは 15 章の C9 を参照）

### 9.2 AIの顔素材の作り方
1. 画像生成AIで、基準になる正面の顔を 1 枚作る。年齢、肌の色、体つきを、動画に映る人物に合わせる。実在の人物に似せない（S1）
2. 同じ人物のまま角度や照明を変えた写真を作る。顔の同一性を保つ生成の手法（InstantID、PuLID など）や、画像編集AIの「同じ人物で角度違い」の指示を使う。**この分野の最新の手法は実装前に確認する（C8）**
3. 合計 10〜20 枚にする。動きの多い動画を扱うなら 20 枚前後
   - 角度：正面、左右の斜め 45 度、真横に近い横顔、少し上向き、少し下向き、見上げ、見下ろし
   - 照明：明るさと光の向きに幅を持たせる
   - 表情：無表情か軽い笑顔でよい（激しい表情は元の動画から写される）
4. 高解像度にする。メガネ、フィルター、強い加工、顔にかかる髪は避ける
5. コンパニオンツール（M4）で、同じ人物に見えるか、角度に偏りがないかを検査する
6. 体が多く映る動画では、顔と首や体の肌の色・質感がずれると合成だとわかるので、肌の色合わせを特に意識する

### 9.3 テスト
- 本番の前に、5〜10 秒のテスト用クリップで設定を決める
- テスト用クリップには、表情が激しい場面、顔が傾く場面、顔が隠れる場面、回転で顔が消えて再び見える場面、全身が映る引きの画、速い動き、髪が顔にかかる場面を含める
- 1 回に 1 つの設定だけを変えて比べる
- 比べ方は 12 章に従う

### 9.4 本番
1. VisoMaster Fusion で、人物ごとに顔素材を割り当てる（複数の写真をまとめて 1 人分の顔の情報として保存する）
2. タイムラインのマーカーを場面の切り替わりごとに置き、シーンプロファイル（10 章）の設定を保存する。ダンスなら振り付けのパートごとに置く
3. 問題のあるフレームを探す機能で確認し、コンパニオンツールの品質チェック（M6）でも確認する
4. 設定をプリセットとして保存し、ジョブ管理機能でまとめて書き出す
5. DaVinci Resolve で仕上げる（9.6 節）

### 9.5 最上位の品質：DFM 専用モデル
1. 中核の方法で何本かの動画の顔を置き換える
2. 品質チェック（M6）で合格したフレームから、AIの顔を切り出して学習用の素材にする（数千枚が目安。M8）
3. DeepFaceLab などで専用モデルを学習させ、DeepFaceLive の DFM 形式に変換する。RTX 3080 では数日かかる
4. VisoMaster Fusion で DFM を使い、AlphaFace と比べる

注意：DeepFaceLab は更新がほとんど止まっている。学習の方式（汎用の学習データを使う方法など）と、DFM への変換の手順は【未確認】。実施前に最新の手順を確認する（C11）。動きの多い動画が多い場合は優先度を上げる。

### 9.6 仕上げ（DaVinci Resolve）
- 首、胸、腕など、見えている肌の色を顔に合わせる（体が多く映る動画では最重要）
- 顔の部分だけ、ノイズ（粒子感）とシャープさを周りに合わせる。顔だけきれいすぎると合成だとわかる
- 速い動きの場面では、顔にも体と同じくらいのブレを足す
- 崩れたフレームは、その部分だけ手で直す
- （任意）ID-V2V の照明を変えるモードで、顔と体の光の当たり方をそろえる【推測】

## 10. VisoMaster Fusion の推奨設定とシーンプロファイル

### 10.1 基本設定

| 項目 | 推奨 | 理由 |
|---|---|---|
| 顔交換モデル | AlphaFace | 極端な角度に強い |
| 顔交換の解像度（Swapper Resolution） | 調整は 256、本番は 512（Auto もある） | 512 は肌や目元を細かく描ける |
| 2つ目の顔交換（Secondary Swapper） | 候補：Inswapper128、InStyleSwapper、SimSwap、GhostFace、CSCS、DFM。混ぜる割合（Blend Amount）を変えて比べる。混ぜない場合とも比べる | 似ている度合いと質感を両立できる場合がある |
| 特徴点検出 | tufa98（顔が傾く場面）／orformer98（顔が隠れる場面） | 場面によって使い分ける |
| 顔の追跡 | ByteTrack をオン | 複数人、取り違え、一瞬画面から外れる場面への対策 |
| 追跡の保持フレーム数（Track Buffer） | 動きの多い動画では長めにする | 回転で顔が消えても同じ人として追い続ける |
| 表情を戻す機能 | 詳細設定で眉、目、口を戻す | R2 |
| 口元・目元 | Restore Mouth、Restore Eyes、Mouth Fit & Align | 口の開きと目元を元の動画に近づける |
| マスク | 遮蔽物＋XSeg＋顔のパーツ分け。横顔用（profile-angle）も使う | 腕、道具、髪が顔にかかる場面に対応 |
| 肌の質感 | ReF-LDM、Texture Transfer、AutoColor | 汗、赤み、肌のきめを保ち、照明になじませる |
| 顔の補正（Face Restorer） | 弱め | 強くすると表情や汗が消え、肌がつるつるになる |
| 顔の形の調整（Face Shaping） | 必要な分だけ控えめに | 見た目を整える仕上げ |
| 同時処理の数（Number of Streams） | 1 から始める | VRAM 10GB での安定のため |

### 10.2 置き換える人物の指定
- 人物ごとに顔素材を割り当てる。似ている度合いの判定の厳しさを調整する
- 似た 2 人が映る場合は判定を厳しくする。ただし厳しくしすぎると、本人の顔も置き換わらないフレームが出る
- 鏡に映った顔も検出される。置き換えに失敗していないか確認する
- 2 人が重なる、立ち位置が入れ替わる場面は、書き出し前に必ず確認する

### 10.3 シーンプロファイル

| ID | 場面 | 例 | 重点を置く設定 |
|---|---|---|---|
| P1 | 表情が激しい | 力む、苦しむ、大笑い、叫ぶ | 表情を戻す機能を強める。口元・目元の復元をオン。顔の補正は弱め |
| P2 | 全身・速い動き | ダンス、スポーツ、引きの画 | 512 モード、Track Buffer を長め、横顔用マスク、AutoColor。仕上げで顔にブレを足す |
| P3 | 顔が隠れる | 腕、道具、髪が顔にかかる | orformer98、遮蔽物マスク＋XSeg＋顔のパーツ分け |
| P4 | 顔が大きく傾く | のけぞる、うつむく、寝転ぶ | tufa98。斜め、見上げ、見下ろしの顔素材を増やす |
| P5 | 会話・正面 | 話す、説明する | 標準設定。Mouth Fit & Align |
| P6 | 複数人 | 2 人以上が映る | 人物ごとの割り当て、ByteTrack、入れ替わる場面の確認 |
| P7 | 照明が変わる | ステージ照明、カラーライト、屋外と屋内の切り替え | AutoColor、Texture Transfer。仕上げで色合わせ |

## 11. コンパニオンツール（AIエージェントの実装範囲）

### 11.1 技術方針
- 言語：Python 3.11
- GUI：PySide6
- 動画処理：FFmpeg / ffprobe
- 顔の検出と似ている度合いの計算：InsightFace（buffalo_l）。学習済みモデルは非商用の研究用ライセンスなので、個人利用の範囲で使う
- 比較用の顔交換：FaceFusion v3.9.1 の CLI（`headless-run`）
- 主な対象 OS：Windows 11
- VisoMaster Fusion の内部（ソースコード、設定ファイルの形式）には依存しない

### 11.2 フォルダ構成

```
project_root/
├─ project.json          # プロジェクト設定と処理の記録
├─ consent_log.json      # 素材の確認記録（S1、S2）
├─ sources/              # 元の動画
├─ faces/<人物ID>/        # AIの顔素材（人物ごと）
├─ clips/                # テスト用クリップ
├─ renders/
│   ├─ visomaster/       # VisoMaster Fusionの出力（ユーザーが保存）
│   └─ facefusion/       # FaceFusionの出力（自動）
├─ compare/              # 比較動画と比較画像
├─ qc/                   # 品質チェックのレポート
├─ dfm_dataset/          # DFM学習用のフレーム
└─ export/               # DaVinci Resolveに渡すファイル
```

1 本の元動画から違う顔のバージョンを複数作る場合は、`renders/` の下をバージョンごとに分け、`project.json` に「元動画・人物ID・設定」の組み合わせを記録する。

### 11.3 モジュール

#### M1：プロジェクト管理
- プロジェクトの作成と読み込み、11.2 節のフォルダの自動作成
- `project.json` に、使ったツールのバージョン、モデル、設定、処理の履歴を記録する
- **完了条件**：新規作成でフォルダ一式ができ、再起動後も同じ状態で開ける

#### M2：素材の取り込みと検査
- ffprobe で解像度、フレームレート、可変フレームレートかどうか、HDR かどうか、音声の有無、長さ、フレーム数を調べて表示する
- 可変フレームレートの動画は、固定フレームレートへの変換を提案する（音ずれを防ぐため）
- HDR の動画は警告し、SDR への変換を提案する（VisoMaster Fusion の HDR 対応は未確認のため。C9）
- 9.1 節の撮影ガイドに合わない点（4K 未満、30fps 以下、暗いなど）を警告する
- 取り込み時に、本人または了承済みであることの確認（S2）を求め、`consent_log.json` に記録する
- **完了条件**：動画を読み込むと情報と警告が表示され、確認しないと取り込めない

#### M3：テスト用クリップの切り出し
- タイムライン上で範囲を選んで切り出す
- 中間ファイルは画質が落ちない形式で保存する。VisoMaster Fusion が読み込める形式を確認してから決める（C10）。読み込めない場合は、画質劣化の少ない設定の H.264 / H.265 にする
- 顔検出の結果から、顔が消える区間、顔が大きく傾く区間、顔が小さい区間の候補を自動で示す（9.3 節の条件を満たすクリップを選びやすくするため）
- **完了条件**：選んだ範囲が切り出され、元の動画の時刻と対応づけて記録される

#### M4：顔素材の管理
- 人物ごとに顔写真を登録する
- 各写真について、顔が 1 つだけ写っているか、顔の部分の解像度が十分か（目安：512px 以上）、メガネがないかを検査する
- InsightFace で顔の向き（左右、上下、傾き）を推定し、角度ごとの枚数の偏りを表示する（例：「左の横顔が不足」）
- 同じ人物の写真どうしが十分に似ているかを計算し、別人に見える写真を警告する
- 登録時に「AIで作った架空の人物である」ことの確認（S1）を求めて記録する
- **完了条件**：写真の一括登録、検査結果の表示、角度ごとの枚数の表示、確認の記録ができる

#### M5：比較動画の作成
- 同じテスト用クリップと顔素材で、FaceFusion の CLI を設定違いで自動実行する
  - 初期の比較：顔交換モデルを alphaface_256 と hyperswap_1a_256 にした 2 本
  - 使う処理：顔交換、表情を戻す機能、顔の補正（弱め）
  - 特徴点検出：hrffa
- 複数人が映るクリップでは、置き換える人物を次の方法で指定する
  - 顔の選択方式を `reference` にし、基準の顔を取り出すフレーム番号と、そのフレームでの顔の順番を指定する。似ている度合いの基準（初期値 0.3）と、必要なら性別での絞り込みも使う【確認済み：`--face-selector-mode`、`--reference-frame-number`、`--reference-face-position`、`--reference-face-distance`、`--face-selector-order`、`--face-selector-gender`】
  - 2 人とも置き換える場合は 2 回に分けて処理する。1 回目の出力に対して 2 回目を実行する
- 顔交換モデル、処理の種類、特徴点検出の引数名は、`--help` で確認してから使う【未確認】
- `renders/visomaster/` に置かれた VisoMaster Fusion の出力を自動で見つける
- 2〜4 本の結果を、ラベル付きで左右（または格子状）に並べた比較動画を作る（FFmpeg の hstack / xstack）
- 同じ時刻のフレームを並べた比較画像も書き出す
- FaceFusion のコンテンツ判定で処理が止まった場合は、エラーとして記録し、そのクリップは比較から外す（S4）
- **完了条件**：ボタン 1 つで、FaceFusion の処理から比較動画の作成までが終わる

#### M6：品質チェック
フレームごとに次を計算し、HTML のレポートを作る。

| 指標 | 計算方法 | 目的 |
|---|---|---|
| 顔の検出漏れ | 元の動画では顔があるのに、出力では検出できないフレーム | 置き換えの失敗を見つける |
| 顔素材との似ている度合い | 出力の顔と顔素材の似ている度合い（ArcFace の埋め込みのコサイン類似度） | 別人に見えるフレームを見つける |
| 元の人物との似ている度合い | 出力の顔と、元の動画の同じフレームの顔との似ている度合い | 置き換え不足（元の顔が残っている）を見つける |
| ちらつき | 隣り合うフレームでの似ている度合いの変化量 | 顔が揺れる区間を見つける |
| 再び現れたときの一貫性 | 顔が消える前と後での似ている度合いの差 | 回転などの後に別人になっていないか |
| 取り違え | 複数人の動画で、割り当てと違う顔になったフレーム | R5 の確認 |

- 基準を下回る区間を一覧にし、その時刻へ移動できるようにする（VisoMaster Fusion で直すため）
- **基準値の決め方**：最初に、ユーザーが「良い」と判断したテスト用クリップの出力で各指標を計算し、その分布から基準値の初期値を決める。ユーザーが後から変えられるようにする
- 表情の再現度、首の境目、肌の色、ブレの合い方は数値化が難しいので、目視で確認するチェックリストとしてレポートに入れる
- **完了条件**：出力動画を指定するとレポートができ、問題区間の一覧から時刻へ移動できる

#### M7：書き出しの整理
- 出力のフレーム数と長さが元の動画と一致するかを確認し、ずれていれば警告する（音ずれ対策）
- DaVinci Resolve に渡す中間ファイルを書き出す（ProRes 422 HQ、または DNxHR HQ）
- 元の音声をそのまま保つ
- 元の動画と同じタイムコードとフレームレートにそろえる
- 「AIで改変した」ことを示すメタデータを付ける（S5）
- **完了条件**：DaVinci Resolve に読み込むと、元の動画と同じ長さとタイミングで並べられる

#### M8：DFM 学習用データの収集（フェーズ 4）
- M6 で合格したフレームから顔の部分を切り出し、学習用の素材として保存する
- 角度ごとの枚数を表示し、偏りを警告する
- **完了条件**：指定した本数の動画から、角度の偏りが少ない学習用素材ができる

### 11.4 作らないもの
- VisoMaster Fusion の改造や、内部の自動操作
- ツールの安全機能を回避する仕組み（S4）
- 実在の人物の顔を検索、取得する機能

## 16. 将来の拡張

### 16.1 LivingSwap（最優先）
- コードが公開されたら、中核の出力を目印のフレームとして使い、もう一段上の品質を狙う
- 動きの多い動画（P2）で最初に試す

### 16.2 ID-V2V での照明調整（検証が必要）
- 顔交換後の動画を元の動画として渡し、照明を変えるモードで、顔と体の光の当たり方をそろえる【推測】
- 公式の動作確認は A100（80GB）8 枚で、モデルファイルは約 96GB。手元では動かさず、fal.ai の API を使う

### 16.3 音声（後回し）
動画の中の特定の人の声だけ、声色を変える機能です。現時点では実装しません。候補だけを記録します。

| 工程 | 候補 |
|---|---|
| 声と背景音を分ける、特定の人の声を取り出す | ClearerVoice-Studio（映像の口の動きを手がかりにした抽出に対応） |

| 声色の変換 | MeanVC2（2026-06）、Vevo2（2026-03）、Seed-VC V2（基準） |

- 声質だけを変える方式なので、長さが変わらず口の動きとずれない
- 日本語でどこまで自然か、息づかいや力んだ声が保たれるかは未確認
- 変換先の声も、AIで作った実在しない声にする。他人の声を変える場合は、その人の了承を取る
